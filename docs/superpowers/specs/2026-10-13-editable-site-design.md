# Редактируемый статический сайт SofiBirdPlush

## Цель
Упростить повседневное редактирование текстов, цен, ссылок, товаров и фотографий, сохранив текущий дизайн и адреса сайта. Пользователь согласовал лёгкую статическую сборку, шаблоны и файлы данных, проверки и повторную публикацию в GitHub Pages.

## Структура
- `site/content/*.json`: данные четырёх страниц и общие контакты/блок об авторе.
- `site/templates/`: шаблоны страниц и общие компоненты меню, товара и галереи. Jinja2 с автоэкранированием и ошибкой при неизвестной переменной.
- `site/assets/`: существующие локальные ресурсы Tilda и пользовательские изображения. Сохраняем рабочие библиотеки и их порядок загрузки.
- `scripts/build.py`: проверяет данные, генерирует четыре готовые HTML-страницы. Без серверного кода и сборки в браузере.
- `scripts/verify.py`: проверяет опубликованные файлы, ссылки, якоря, галереи, JavaScript и отсутствие кредита Tilda.
- `requirements.txt`: зависимости Python для сборки и проверки.

## Контракт редактирования
Товар задаётся объектом: уникальный числовой ID для совместимости с Tilda, название, цена, валюта, описание, кнопка, фотографии и настройки существующего оформления. Порядок объектов определяет порядок блоков. Фотографии задаются путями относительно `site/`, независимо от глубины страницы. Для текста с форматированием используются явно названные поля `*_html`; обычный текст и атрибуты экранируются. Меню содержит подпись и адрес каждого пункта. Общие ссылки определяются один раз.

## Ограничения
- Адреса `/`, `/fur/`, `/ceramic/`, `/prints/` и работа под `/sofibirdsofi/` сохраняются.
- Локальный просмотр готового сайта: `python3 -m http.server 8000 --directory site`.
- Внешний вид, тексты, фотографии, внешние адреса и взаимодействия сохраняются; canonical и Open Graph URL обновляются на Pages.
- `scripts/mirror.py` не запускается. Блок `#tildacopy` не возвращается.
- В артефакт Pages входят только готовые HTML и ресурсы; исходные шаблоны/данные не публикуются.
- До записи страниц сборка проверяет все данные и рендерит все страницы, чтобы ошибка не оставляла частично обновлённый сайт.

## Проверка и публикация
Тесты сборки проверяют изменение текста/цены, добавление товара/фото, относительные пути, экранирование, ошибки данных и воспроизводимость. Проверка файлов проходит перед push и в Actions. Перед публикацией проверяем четыре страницы, меню и галереи на широком и мобильном экранах. После commit и push в `main` ждём успешного Pages workflow и проверяем публичные страницы. Откат — возврат предыдущего коммита через revert и повторная публикация.
