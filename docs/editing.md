# Как редактировать сайт

## Локальный просмотр

Один раз создайте окружение и установите зависимости из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

При следующих запусках достаточно активировать окружение:

```sh
source .venv/bin/activate
python3 scripts/build.py
python3 -m http.server 8000 --directory site
```

Адреса для проверки:

- http://localhost:8000/
- http://localhost:8000/fur/
- http://localhost:8000/ceramic/
- http://localhost:8000/prints/

После правки JSON, шаблона или списка фотографий выполните `python3 scripts/build.py` в другом терминале и обновите браузер. После правки CSS сборка не нужна. Для остановки сервера нажмите Ctrl+C.

Не редактируйте готовые `site/index.html` и `site/*/index.html` вручную: следующая сборка их заменит.

## Изменить название, цену или описание

Откройте JSON нужного каталога. В массиве `sections` найдите объект с `"type": "product"` и нужным `title`.

- `title` — название обычным текстом.
- `price` — цена строкой, например `"95"` или `"85-125"`.
- `currency` — знак валюты.
- `description_html` — описание с форматированием.
- `subtitle_html` — необязательная подпись под названием.
- `button.label` — подпись кнопки.
- `button.href` — ссылка или общий контакт, например `"@bluesky"`.

В полях с суффиксом `_html` разрешена разметка: `<br>` для переноса строки, `<strong>...</strong>` для выделения, `<a href="...">...</a>` для ссылки. Кавычки внутри JSON-строки экранируются: `\"`. Названия и подписи без `_html` пишите обычным текстом: сборка сама экранирует `<`, `>` и `&`.

## Добавить товар

Скопируйте объект товара в `sections`, поставьте запятую между объектами и измените его данные. У нового товара должен быть уникальный `id` из 1–16 цифр, например `"9000000001"`. Эти ID нужны существующим библиотекам для инициализации галерей. Не меняйте ID действующих блоков без необходимости.

Минимальный объект:

```json
{
  "type": "product",
  "id": "9000000001",
  "title": "New bird",
  "price": "95",
  "currency": "€",
  "description_html": "Handmade with love<br>Ready for adoption",
  "button": {
    "label": "adopt",
    "href": "@bluesky"
  },
  "images": [
    {
      "src": "assets/new-bird.jpg",
      "alt": "A handmade blue plush bird"
    }
  ]
}
```

Настройки `space_top`, `button_color` и `description_size` необязательны. По умолчанию: 120 пикселей отступа сверху, цвет кнопки `#ff623b`, размер описания 20 пикселей. Чтобы сохранить оформление соседней карточки, скопируйте её настройки.

Порядок объектов в `sections` определяет порядок блоков. В каталогах вставляйте товары после вступления и перед блоком `anchor-about`, чтобы раздел об авторе оставался внизу. Чтобы убрать товар, удалите его объект. Остальные блоки и якоря сохраняйте.

## Добавить или заменить фотографию

Поместите изображение в `site/assets/`, используя понятное имя без пробелов, например `berry-jam-side.jpg`. Затем измените массив `images` у нужного товара:

```json
"images": [
  {
    "src": "assets/berry-jam-front.jpg",
    "preview": "assets/berry-jam-front-small.jpg",
    "alt": "Front view of the berry jam plush bird"
  },
  {
    "src": "assets/berry-jam-side.jpg",
    "alt": "Side view of the berry jam plush bird"
  }
]
```

`src` — основное изображение, `preview` — необязательное облегчённое превью. Если превью отсутствует, используется `src`. Пути всегда начинаются с `assets/` и задаются относительно `site/`: не добавляйте `../` для вложенных каталогов. Порядок фотографий задаётся порядком объектов; стрелки и миниатюры появятся автоматически при нескольких снимках.

Портфолио на главной редактируется аналогично в блоке `"type": "gallery"`. Фон первого экрана находится в `images` блока `hero`, изображение для заказа — в блоке `commissions`.

## Изменить общие ссылки или блок об авторе

В `site/content/common.json`:

- `links.bluesky` — общий контакт для заказа; используется в кнопках товаров, первом экране и разделе заказа.
- `links.donation` — адрес пожертвований.
- `links.twitter`, `links.instagram`, `links.tiktok` — ссылки в меню.
- `about` — текст, подписи и фото автора для всех четырёх страниц.
- `base_url` — полный адрес опубликованного сайта с `/` в конце; используется для canonical и Open Graph.

В ссылках меню, кнопках и `href` внутри HTML-полей можно использовать имя общего адреса: `@bluesky`, `@donation` и т. д. Для страницы сайта используйте `fur/`, `ceramic/`, `prints/`; сборка сама учитывает вложенность. Якорь `#about` остаётся на текущей странице.

Заголовок страницы, описание для соцсетей и изображение предпросмотра задаются полями `title`, `description`, `social_image` в JSON страницы. Они не меняют видимый заголовок вступления — он находится в соответствующем блоке `sections`.

## Изменить оформление

Общая разметка — `site/templates/base.html`; компоненты — `site/templates/components/`; первый экран, вступление, заказ и якоря — `site/templates/sections/`.

Собственные CSS-правки добавляйте в `site/assets/site.css`. Существующие библиотеки и стили с хешами в именах сохраняйте: это локальные зависимости экспортированного дизайна.

## Проверить и опубликовать

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 scripts/build.py --check
python3 scripts/verify.py
```

Сборка сообщит об ошибке JSON, повторяющемся ID, пустой галерее, неизвестной переменной или отсутствующей фотографии до записи страниц. Проверка найдёт отсутствующие ресурсы, неверные якоря и ошибки JavaScript.

Проверьте четыре страницы, переходы меню, кнопки и галереи при широком и узком окне. Затем закоммитьте исходники и готовые HTML и отправьте изменения в `main`. Actions повторно соберёт сайт и проверит его перед деплоем, поэтому правки данных можно публиковать и через GitHub.

```sh
git push origin main
gh run list --workflow pages.yml --limit 1
gh run watch <ID> --exit-status
```

Для проверки состава публикации можно выполнить `python3 scripts/package.py --output /tmp/sofibird-publish-preview`, указав новую пустую папку. Там будут только готовые страницы, ресурсы и `.nojekyll`.
